# Judger - 判断器

## 说明

判断器用于在 Judge 的任务执行过程中读取分析结果，并生成判断结果。

一次评价任务通常先由分析器生成 `Analysis`，再由判断器根据这些分析结果计算评价值。
如果判断逻辑直接写入分析器，数据处理、评价规则、报警判断和展示下沉会相互耦合，不利于扩展和维护。

判断器将具体的分析结果评价过程封装为统一的执行器接口。
每个判断器通过 `JudgerInfo` 配置类型和参数，系统按照判断器信息的顺序创建并执行判断器执行器。

判断器是任务执行链路中的第二个处理阶段，整体作业流程如下：

![Judge 作业流程](./images/JudgeWorkFlow.png "Judge 作业流程")

在该流程中，判断器位于分析器之后、可视化器之前，负责生成后续可视化和报警阶段需要读取的 `Judgement`。

判断器通过 `Context` 读取判断器变量、已有分析结果和已有判断结果，也可以调用 [Provide](./Provide.md) 查询外部数据，
并将处理结果保存为当前任务的 `Judgement`。

本文介绍判断器本身的信息实体、接口、生命周期和运行机制；
项目内置的具体实现请参阅 [Preset Judger Implements](./PresetJudgerImplements.md)。

## JudgerInfo

`JudgerInfo` 描述部件中的一个判断器运行实例，关键字段如下：

| 字段         | 类型        | 说明                                                         |
|--------------|-------------|--------------------------------------------------------------|
| `key`        | `LongIdKey` | 判断器信息主键。                                             |
| `sectionKey` | `LongIdKey` | 判断器所属的部件主键。                                       |
| `index`      | `int`       | 判断器在所属部件中的执行顺序，数值较小的判断器优先执行。     |
| `enabled`    | `boolean`   | 是否启用；只有启用的判断器信息会进入作业本地缓存和执行链路。 |
| `type`       | `String`    | 判断器类型标识，用于匹配对应的 `JudgerMaker`。               |
| `param`      | `String`    | 判断器构造参数，具体格式由判断器类型决定。                   |
| `remark`     | `String`    | 备注。                                                       |

一个部件可以配置多个 `JudgerInfo`。
系统读取指定部件下全部启用的判断器信息，并按照 `index` 升序构造执行链。

同一种 `type` 可以对应多条 `JudgerInfo`。
因此，同一种判断器实现可以使用不同参数构造多个运行实例，并在同一个部件中生成不同维度的判断结果。

判断器按 `JudgerInfo.key` 进入作业本地缓存中的信息映射和实例映射。
当判断器信息未启用时，系统不会为其构造判断器，也不会在任务中执行该判断器。

如果 `type` 没有对应的制造器，系统抛出不支持判断器类型异常。
如果 `param` 无法被对应实现解析，系统在构造判断器时抛出判断器制造异常。

## JudgerVariable

`JudgerVariable` 用于保存判断器自身需要跨任务维护的状态。

判断器变量的主键由判断器信息主键和变量字符串标识组成：

| 字段               | 类型     | 说明                             |
|--------------------|----------|----------------------------------|
| `judgerInfoLongId` | `Long`   | 变量所属的判断器信息主键。       |
| `variableStringId` | `String` | 判断器内部约定的变量字符串标识。 |

变量实体的关键字段如下：

| 字段           | 类型                | 说明                 |
|----------------|---------------------|----------------------|
| `key`          | `JudgerVariableKey` | 判断器变量复合主键。 |
| `valueType`    | `int`               | 变量值类型。         |
| `stringValue`  | `String`            | 字符串值。           |
| `longValue`    | `Long`              | 长整型值。           |
| `doubleValue`  | `Double`            | 双精度浮点值。       |
| `booleanValue` | `Boolean`           | 布尔值。             |
| `dateValue`    | `Date`              | 日期值。             |

变量值类型与有效值字段的对应关系如下：

| 类型常量                      | 枚举值 | 有效字段       |
|-------------------------------|--------|----------------|
| `VARIABLE_VALUE_TYPE_STRING`  | `0`    | `stringValue`  |
| `VARIABLE_VALUE_TYPE_LONG`    | `1`    | `longValue`    |
| `VARIABLE_VALUE_TYPE_DOUBLE`  | `2`    | `doubleValue`  |
| `VARIABLE_VALUE_TYPE_BOOLEAN` | `3`    | `booleanValue` |
| `VARIABLE_VALUE_TYPE_DATE`    | `4`    | `dateValue`    |

判断器变量归属于 `JudgerInfo`，不归属于某一次任务。
同一个判断器实例在不同任务中可以通过相同的 `variableStringId` 读取和更新同一份状态。

变量适合保存游标、动态阈值、累计计数、上次判断时间或其它需要跨任务延续的小型状态。
任务本次执行产生的业务评价应保存为 `Judgement`，不应使用判断器变量代替任务判断结果。

## JudgerSupport

`JudgerSupport` 描述当前节点支持的一种判断器类型，关键字段如下：

| 字段           | 类型          | 说明                                          |
|----------------|---------------|-----------------------------------------------|
| `key`          | `StringIdKey` | 判断器类型标识，与 `JudgerInfo.type` 对应。   |
| `label`        | `String`      | 判断器类型的显示名称。                        |
| `description`  | `String`      | 判断器类型的说明。                            |
| `exampleParam` | `String`      | 示例构造参数。                                |

判断器注册通常同时实现 `JudgerMaker` 和 `JudgerSupporter`。
`JudgerMaker` 负责根据类型和参数构造判断器，`JudgerSupporter` 负责提供类型、标签、说明和示例参数。

系统启动或执行支持重置时，会收集 Spring 容器中的 `JudgerSupporter` 并更新 `JudgerSupport`。
管理端可以读取这些信息，展示当前部署实际加载的判断器类型及其示例参数。

`JudgerSupport` 只描述类型支持能力，不代表已经存在对应的 `JudgerInfo`，
也不代表某个部件的作业本地缓存中已经构造了该类型的判断器。

## Judgement

`Judgement` 用于保存一次任务内部产生的判断结果。

判断结果的主键由任务主键和数据字符串标识组成：

| 字段           | 类型     | 说明                                           |
|----------------|----------|------------------------------------------------|
| `taskLongId`   | `Long`   | 判断结果所属的任务主键。                       |
| `dataStringId` | `String` | 判断结果的数据标识，由判断器自行约定。         |

判断结果实体的关键字段如下：

| 字段      | 类型           | 说明                                                   |
|-----------|----------------|--------------------------------------------------------|
| `key`     | `JudgementKey` | 判断结果复合主键。                                   |
| `value`   | `double`       | 判断值，一个范围为 `[0.0, 1.0]` 的归一化数值。         |
| `message` | `String`       | 判断消息，用于说明判断值的含义，或解释判断值如何得出。 |

`Judgement.value` 写入时会进行范围校验。
如果判断器写入小于 `0.0` 或大于 `1.0` 的判断值，系统会拒绝写入并抛出无效判断值异常。

`Judgement` 归属于任务，描述本次任务产生的判断结果。
作业进入报警阶段时，系统会将本次任务中的全部 `Judgement` 同步为部件维度的当前裁决结果 `Verdict`。

`Verdict` 按 `sectionKey` 和 `dataStringId` 保存某个数据点当前最新的判断值与判断消息。
报警阶段根据 `Verdict.value` 和 `AlarmSetting.threshold` 计算报警模态。

## 接口

### Judger

判断器 `Judger` 是创建判断器执行器的入口，主要方法如下：

| 方法签名                                        | 说明                       |
|-------------------------------------------------|----------------------------|
| `Executor newExecutor() throws JudgerException` | 创建一个新的判断器执行器。 |

具体实现通常继承 SDK 中的 `AbstractJudger`，并实现创建执行器的模板方法。
判断器可以保存构造参数、已编译脚本、映射规则或创建执行器所需的其它只读状态。

判断器实例会进入作业本地缓存，并被同一部件的多个任务复用。
具体实现如果在判断器实例中保存可变状态，需要自行考虑并发任务访问时的线程安全问题。

### Executor

`Judger.Executor` 表示一次任务中执行一个判断器的执行器，主要方法如下：

| 方法签名                        | 说明                       |
|---------------------------------|----------------------------|
| `void init(Context context)`    | 初始化执行器并设置上下文。 |
| `void judge() throws Exception` | 执行判断逻辑。             |

具体实现通常继承 SDK 中的 `AbstractExecutor`。
抽象实现保存 `Context`，具体执行器在 `judge()` 中使用该上下文读取分析结果并持久化判断结果。

系统每次执行任务时都会为每个判断器创建新的执行器。
执行器只服务于当前任务，不会进入作业本地缓存，也不会在不同任务之间复用。

`Executor` 没有显式的关闭或销毁方法。
如果执行器在 `judge()` 中临时打开流、连接或其它资源，应在方法内部使用可靠的清理机制及时释放。

### Context

`Judger.Context` 表示判断器执行时可访问的任务上下文。
上下文由系统创建，并绑定当前部件、判断器信息和任务。

上下文提供的主要能力如下：

| 能力           | 相关方法                                                                                  | 说明                                            |
|----------------|-------------------------------------------------------------------------------------------|-------------------------------------------------|
| 获取当前对象   | `getSectionKey()`、`getJudgerInfoKey()`、`getTaskKey()`                                   | 获取当前部件、判断器信息和任务主键。            |
| 更新任务信息   | `updateTaskModal(...)`、`createTaskEvent(...)`                                            | 更新任务锚点消息并记录任务事件。                |
| 维护判断器变量 | `inspectJudgerVariable(...)`、`upsertJudgerVariable(...)`、`removeJudgerVariable(...)`    | 读取、写入和删除判断器自身状态。                |
| 读取分析结果   | `inspectAnalysis(...)`                                                                    | 读取当前任务的分析结果。                        |
| 下载图片结果   | `downloadPictureFile(...)` 等方法                                                         | 下载分析图片、图片流、缩略图及图片包条目。      |
| 下载文件结果   | `downloadFileFile(...)` 等方法                                                            | 下载分析文件、文件流及文件包条目。              |
| 维护判断结果   | `inspectJudgement(...)`、`upsertJudgement(...)`、`removeJudgement(...)`                   | 读取、写入和删除当前任务的判断结果。            |
| 查询提供       | `lookupProvide(ProvideLookupInfo info)`                                                   | 通过统一的 Provide 查询链路访问外部或辅助数据。 |

判断器可以读取当前任务中已经存在的判断结果。
由于判断器按照 `index` 升序执行，后续判断器可以使用前序判断器写入的 `Judgement` 构建分阶段评价链路。

通过上下文下载文件流或图片流时，如果返回对象包含输入流，调用方有义务关闭该输入流。

### JudgerMaker

`JudgerMaker` 根据判断器类型和参数构造判断器，主要方法如下：

| 方法签名                                                              | 说明                         |
|-----------------------------------------------------------------------|------------------------------|
| `boolean supportType(String type)`                                    | 判断是否支持指定判断器类型。 |
| `Judger makeJudger(String type, String param) throws JudgerException` | 根据类型和参数构造判断器。   |

系统依次检查当前 Spring 容器中的制造器，并使用第一个支持指定类型的制造器。
制造器应完成参数解析、参数校验以及脚本编译等构造阶段操作。

### JudgerSupporter

`JudgerSupporter` 用于描述一个判断器类型，主要方法如下：

| 方法签名                       | 说明                 |
|--------------------------------|----------------------|
| `String provideType()`         | 提供判断器类型标识。 |
| `String provideLabel()`        | 提供显示名称。       |
| `String provideDescription()`  | 提供类型说明。       |
| `String provideExampleParam()` | 提供示例参数。       |

SDK 中的 `AbstractJudgerRegistry` 同时实现 `JudgerMaker` 和 `JudgerSupporter`，适合用于注册一个固定类型的判断器。

## 判断器的生命周期

### 构造

系统首次获取指定部件的作业本地缓存时，读取该部件下全部已启用的 `JudgerInfo`，并按照 `index` 升序排列。

对于每条判断器信息，系统使用 `type` 查找支持该类型的 `JudgerMaker`，
再将 `type` 和 `param` 传递给制造器构造 `Judger`。

构造完成的判断器以 `JudgerInfo.key` 为键保存到作业本地缓存。
参数解析、脚本编译和不可变规则构造通常应在此阶段完成，避免每次任务执行时重复处理。

作业本地缓存构造过程中，如果任意判断器构造失败，整个部件的缓存获取失败，任务无法进入正常分析阶段。

### 创建执行器

任务完成分析阶段后，系统按照作业本地缓存中的判断器信息主键列表依次处理判断器。

系统从实例映射中取得 `Judger`，调用 `newExecutor()` 创建新的执行器。
同一个缓存中的判断器可以为多个任务分别创建执行器。

执行器应保存本次执行所需的临时状态，不应假设同一个执行器会被重复用于其它任务。

### 初始化

系统为当前判断器创建 `Context`，并绑定以下信息：

| 信息            | 说明                           |
|-----------------|--------------------------------|
| `sectionKey`    | 当前任务对应的部件主键。       |
| `judgerInfoKey` | 当前正在执行的判断器信息主键。 |
| `taskKey`       | 当前任务主键。                 |

随后，系统调用执行器的 `init(Context)` 方法。
SDK 的 `AbstractExecutor` 会保存该上下文，供 `judge()` 使用。

`init(Context)` 不声明受检异常，通常只用于设置上下文。
复杂参数校验和可能失败的运行期准备工作可以在判断器构造阶段或 `judge()` 开始时完成。

### 执行判断

初始化完成后，系统调用执行器的 `judge()` 方法。

判断器可以通过上下文读取分析结果、下载分析附件、读取已有判断结果、维护判断器变量、执行 Provide 查询、更新任务信息，
并将判断结果写入当前任务。

前一个判断器执行完成后，系统才会创建并执行下一个判断器的执行器。
当前实现不会并行执行同一个部件中的多个判断器。

所有判断器执行完成后，系统记录判断完成事件和耗时，并继续进入可视化阶段。

`Judger` 和 `Executor` 接口没有显式的销毁回调。
清除作业本地缓存后，系统不再持有其中的判断器实例，但不会主动调用判断器的资源关闭方法。
需要长期持有外部资源的自定义实现应谨慎设计资源生命周期，避免依赖不存在的销毁回调。

## 工作机制

### 作业本地缓存

作业本地缓存以 `Section.key` 为键，保存部件以及该部件的分析器、判断器、可视化器信息与实例，
同时保存部件的报警设置快照。

判断器相关内容包括：

| 内容               | 说明                                           |
|--------------------|------------------------------------------------|
| 判断器信息主键列表 | 保存执行顺序，按 `JudgerInfo.index` 升序排列。 |
| 判断器信息映射     | 以 `JudgerInfo.key` 为键保存配置信息。         |
| 判断器实例映射     | 以 `JudgerInfo.key` 为键保存 `Judger`。        |

缓存未命中时，系统读取部件及其已启用的判断器信息并构造判断器；缓存命中时直接复用已有实例。

修改 `JudgerInfo.type`、`param`、`index` 或 `enabled` 后，已经存在的作业本地缓存不会自动重建。
需要清除作业本地缓存，使后续任务重新读取配置并构造执行链。

### 执行顺序

判断器信息通过 `child_for_section_enabled_index_asc` 预设查询，
只选择指定部件下已启用的记录，并按照 `index` 升序排列。

任务判断阶段按照该列表串行执行判断器。
如果多个判断器的 `index` 相同，不应依赖这些记录之间的固定先后顺序；需要确定依赖关系时，应配置不同的索引值。

判断器整体位于分析阶段之后、可视化阶段之前。
因此，判断器可以读取全部分析器写入的 `Analysis`，可视化器可以读取判断器写入的 `Judgement`。

### 判断结果与裁决

`Judgement` 归属于任务，用于保存本次任务产生的判断结果。
判断器可以插入、更新或删除当前任务中的判断结果。

报警阶段开始时，系统读取本次任务下的全部 `Judgement`，并将它们同步为部件维度的 `Verdict`。
如果本次任务没有任何判断结果，系统不会更新该部件已有的裁决结果。

`Verdict` 归属于部件，用于表示某个部件和数据点当前最新的判断值与判断消息。
报警计算读取 `Verdict`，并根据同一数据点下按阈值降序排列的 `AlarmSetting` 生成最新报警模态。

### 判断结果与变量

`Judgement` 归属于任务，用于表达本次任务的评价输出。
`JudgerVariable` 归属于判断器信息，用于保存跨任务状态。

判断器应使用当前 `JudgerInfo.key` 维护自身变量，避免访问其它判断器的状态。
同一个判断器可以同时写入多个 `Judgement`，也可以读取前序判断器写入的判断结果作为后续评价输入。

判断器上下文不会为多个操作提供整体事务语义。
如果执行器先写入若干结果，随后发生异常，已经完成的操作是否保留取决于对应操作处理器的事务边界。
自定义判断器不应假设整个 `judge()` 方法失败后所有副作用都会自动回滚。

### 异常处理

判断器机制使用统一异常类型隔离构造和执行阶段的差异：

| 异常                              | 说明                                     |
|-----------------------------------|------------------------------------------|
| `UnsupportedJudgerTypeException`  | 没有制造器支持指定的判断器类型。         |
| `JudgerMakeException`             | 判断器参数解析、脚本编译或实例构造失败。 |
| `JudgerException`                 | 创建判断器或执行器过程中发生的通用异常。 |
| `JudgerExecutionException`        | 判断器执行时发生参数、数据或转换异常。   |
| `InvalidJudgementValueException`  | 判断结果值超出 `[0.0, 1.0]` 范围。       |

执行器的 `judge()` 可以抛出任意异常。
判断阶段中的任意判断器执行失败时，系统停止执行后续判断器，不再进入可视化、报警和下沉阶段。

系统会记录警告日志，创建作业失败事件，并将任务状态置为失败。
任务事件只包含通用失败提示，详细异常原因需要通过系统日志排查。

## 运维与配置

判断器扩展通过 `opt/opt-judger.xml` 加载。
发行包中的默认文件预留了预设判断器的组件扫描配置，但默认均被注释。

启用对应判断器时，取消相应 `context:component-scan` 的注释，并重启节点使 Spring 重新加载组件。
具体配置方式请参阅 [Opt Directory](./OptDirectory.md)。

启动器配置 `judge/launcher.properties` 中的
`com.dwarfeng.judge.launcher.reset_judger_support` 用于控制程序启动完成后是否重置判断器支持信息。
该配置只影响支持信息重置，不会自动清除已经存在的作业本地缓存。

Telqos 中与判断器相关的常用命令如下：

| 命令                     | 说明                                                                   |
|--------------------------|------------------------------------------------------------------------|
| `jlc -l <section-id>`    | 查看指定部件的作业本地缓存，包括判断器信息、执行顺序和判断器实例。     |
| `jlc -c`                 | 清除全部作业本地缓存，使后续任务重新读取分析器、判断器和可视化器配置。 |
| `support --reset-judger` | 根据当前加载的判断器注册器重置 `JudgerSupport`。                       |

`support --reset-judger` 只重置支持信息，不会清除作业本地缓存，也不会重新构造已经缓存的判断器。

排查判断器配置问题时，可以分别确认：

1. `opt-judger.xml` 是否加载了对应实现包。
2. `JudgerSupport` 中是否存在对应类型。
3. `JudgerInfo` 是否归属于正确部件，且已启用。
4. `JudgerInfo.type` 和 `param` 是否符合具体实现约定。
5. `jlc -l` 是否可以成功构造并显示判断器实例。
6. 配置变更后是否执行了 `jlc -c`。
7. 判断器依赖的分析结果、前序判断结果、判断器变量和 Provide 查询数据是否存在且类型正确。

判断器实例可能被多个任务并发复用。
对于耗时较长的判断逻辑，应关注任务执行线程占用、外部查询耗时、结果数量以及脚本实现的线程安全性。
